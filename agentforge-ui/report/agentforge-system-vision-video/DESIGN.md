# AgentForgeAI Ideal IDE Walkthrough - Visual Identity

## Style Prompt

Use the existing AgentForgeAI screenshots as the visual reference: a light technical IDE workspace with restrained panels, thin neutral borders, compact information density, and emerald/teal active states. The video is a product walkthrough of the ideal experience: a user opens a team instance, writes a goal in chat, sees an iFlow generated automatically, approves a workflow gate, monitors orchestration, saves knowledge and returns to completed output. It should feel like real software being used, not a presentation about software.

## Colors

- Canvas: `#F6F8FA`
- Surface: `#FFFFFF`
- Surface muted: `#EEF3F1`
- Border: `#CBD5D1`
- Text primary: `#111827`
- Text muted: `#667085`
- Emerald action: `#078B72`
- Teal link: `#15B8A6`
- Amber warning: `#D88A00`
- Red risk: `#C43D3D`
- Deep slate: `#172033`

## Typography

- Statements and scene titles: `Georgia`, serif, weight 700.
- UI/body labels: `Aptos`, `Segoe UI`, sans-serif, weight 400-700.
- IDs, schemas, permissions, counters: `Cascadia Code`, `Consolas`, monospace.

## Motion

- Medium-energy SaaS explainer.
- Primary transition: covered push/wipe with emerald system rail when navigating between IDE modules.
- Accent motion: cursor travel, click pulse, message arrival, node activation and progress fill.
- Entrances should resemble panels loading and task state changing; no jump cuts.
- Use slow ambient grid/routing-line motion in the background.

## What NOT to Do

- Do not use dark neon cyber styling.
- Do not use large decorative gradient blobs.
- Do not make repeated equal card grids dominate the whole video.
- Do not present the current broken/mock screens as the final state.
- Do not turn the video into architecture slides; show IDE actions and feedback.
- Do not use vague labels; each generated flow/task/module should be understandable to a user.
